# Техническое задание

## Проект: Cognitive Offload System (COS)

**Формат:** Telegram-бот
**Цель:** Полное вынос операционки (финансы, время, задачи, заметки) из головы пользователя для освобождения когнитивных ресурсов.

---

## 1. Цели проекта

### 1.1 Основная цель

* Снизить когнитивную нагрузку пользователя до уровня: *«думать о расходах, хвостах и забытых делах — не моя задача»*.

### 1.2 Задачи

* Фиксация реальности в моменте (расходы, время, задачи, мысли).
* Исключение необходимости держать данные в голове.
* Быстрый ввод данных (≤ 20 секунд).
* Анализ данных **вне** Telegram.

---

## 2. Архитектурные принципы

1. Один источник правды.
2. Минимальный ввод.
3. Нет записи = не существует.
4. Система тупая, пользователь умный.
5. Анализ отделён от сбора данных.

---

## 3. Общая архитектура

```
Telegram Client
   ↓
Telegram Bot (aiogram)
   ↓
Raw Storage (PostgreSQL / SQLite)
   ↓
Export Layer (CSV / Google Sheets)
```

## 4. Интерфейс пользователя (UX)

### 4.1 Reply Keyboard (постоянный)

* 💸 Расход
* ⏱ Лог времени
* 🧠 Задача
* 📝 Заметка

---

## 5. Модуль: Финансы (Finance Core)

### 5.1 Цель

* Учёт расходов и обязательств.
* Расчёт burn-rate.

### 5.2 Категории (фиксированные)

* Обязательное
* Проекты
* Еда
* Инфра
* Импульс

### 5.3 UX-флоу

1. Inline-кнопки: выбор категории.
2. Reply: ввод суммы (число).
3. Reply (опционально): комментарий.

### 5.4 Данные

* date
* category
* amount
* comment

---

## 6. Модуль: Лог времени и энергии

### 6.1 Цель

* Определение типов нагрузки и утечек энергии.

### 6.2 Типы активности

* Арх
* Реал
* Рутина
* Комм
* Хаос
* Отдых
* Сон

### 6.3 Намерение

* План
* Вынужд
* Утекло

### 6.4 Энергия

* +1
* 0
* -1

### 6.5 UX-флоу

1. Inline: тип активности.
2. Inline: намерение.
3. Inline: энергия.
4. Reply (опционально): комментарий.

### 6.6 Данные

* timestamp
* activity_type
* intention
* energy
* comment

---

## 7. Модуль: Управление задачами (Task Dispatcher)

### 7.1 Цель

* Контроль обязательств и очереди выполнения.

### 7.2 Типы задач

* Арх
* Реал
* Рутина

### 7.3 Статусы

* СЕЙЧАС
* ЖДЁТ

### 7.4 UX-флоу

1. Inline: тип задачи.
2. Inline: статус.
3. Reply: название задачи.
4. Inline (опционально): устройство A→B / B→A / —.

### 7.5 Ограничения

* Очередь "СЕЙЧАС": максимум 5 задач.

### 7.6 Данные

* title
* task_type
* status
* device
* created_at

---

## 8. Модуль: Заметки (Brain Dump)

### 8.1 Цель

* Сброс когнитивного давления.

### 8.2 UX-флоу

* Reply: свободный текст.

### 8.3 Данные

* text
* timestamp

---

## 9. Напоминания (Remember System)

### 9.1 Цель

* Принудительный регулярный ввод данных.

### 9.2 Поведение

* 3–5 уведомлений в день.
* Фиксированный текст.
* Без вежливых форм.

### 9.3 Примеры сообщений

* "Нет записей. Фиксируй."
* "Ты живёшь без логов."

## 11. Нефункциональные требования

* Среднее время ввода: ≤ 20 секунд.
* Отказоустойчивость.
* Отсутствие сложной авторизации (один пользователь).
* Минимум зависимостей.

---

## 12. Критерии успешности MVP

Через 7–10 дней использования пользователь должен уметь ответить:

1. Где теряется энергия?
2. Хватает ли доходов на обязательные расходы?
3. Перегружен ли он задачами?
